Overview

The corrected architecture is Supabase-primary while preserving Express. React Native handles UI/session state, Supabase Auth handles account/session primitives, Express verifies Supabase JWTs and runs business logic, and Gemini plus the existing RAG implementation remain backend-only.

Self-Declared Profile Policy

Students may edit their own academic profile because the FYP prototype is not integrated with the university information system. Programme, faculty, CGPA, academic standing, trimester, and credits are SELF-DECLARED, UNVERIFIED, and NOT CONNECTED TO UTAR SYSTEM.

CRITICAL Do not define a separate enrollment-mode field. Use `academic_standing`: NORMAL, PROBATION, WARNING, TERMINATED, GRADUATED. Minimum demo may support NORMAL and PROBATION only.

Supabase Security
  • SECURITY Anon/publishable Supabase key may exist in the mobile app.
  • CRITICAL Service-role key must never exist in the mobile app.
  • CRITICAL Gemini API key remains backend-only.
  • CRITICAL RLS enabled on all user-owned tables.
  • SECURITY Express verifies Supabase access tokens.
  • SECURITY Students read/write only their own permitted records.
  • CRITICAL Academic document upload is admin-only through trusted backend credentials.
  • SECURITY Storage policies protect profile images and academic documents.
End-to-End Flow Consistency
  1. React Native auth UI uses Supabase Auth for sign up, email verification, login, restore session, refresh session, forgot/reset password, and logout.
  2. React Native sends Supabase access token to Express for protected business endpoints.
  3. Express verifies JWT and maps `sub` to `student_profiles.user_id`.
  4. Express labels profile context as SELF-DECLARED, UNVERIFIED, NOT CONNECTED TO UTAR SYSTEM.
  5. Express runs AI Chat, RAG retrieval, Academic Rules, advisor escalation, and document processing.
  6. Supabase PostgreSQL stores profiles, conversations, messages, sources, documents, chunks, rules, and optional FYP tables.
  7. React Native handles answer status, citations, advisor actions, validation errors, loading and empty states.
Future University Integration

The current architecture is not connected to UTAR systems. Future integration may replace student-editable fields with official student portal synchronization, administrator-managed profiles, verified academic records, read-only institution-owned fields, and UTAR SSO. This is future scope, not current architecture.
